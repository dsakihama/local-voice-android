# Stack Pivot — 2026-06-19

## Decision

Replace the ONNX Runtime inference stack (Whisper Small int8 + Phi-2 int4) with Google's ML Kit GenAI APIs running Gemini Nano on-device via AICore.

| Component | Before | After |
|---|---|---|
| Speech-to-text | Whisper Small int8 (ONNX Runtime) | ML Kit GenAI Speech Recognition API — Advanced mode (Alpha) |
| Text cleanup / intent | Phi-2 int4 (ONNX Runtime) | ML Kit GenAI Prompt API (Beta) |
| Runtime | ONNX Runtime + NNAPI delegate | AICore (Android system service) |
| Hardware | CPU / NNAPI fallback | Tensor TPU (managed by OS) |
| Model assets | ~2.57 GB, delivered via first-run download | 0 MB — models live in AICore, managed by Android OS |

---

## Why

**1. Hardware fit.** The Pixel 10 Pro XL's Tensor G5 chip is purpose-built to run Gemini Nano. ONNX Runtime uses NNAPI to reach the NPU, but NNAPI falls back to CPU for unsupported ops — a known performance ceiling. AICore goes directly to the Tensor TPU with no fallback penalty.

**2. Performance gap on the cleanup step.** Phi-2 via ORT on NNAPI would likely land at 2–8 tokens/second. Gemini Nano v3 via AICore on Pixel 10 Pro benchmarks at ~940 tokens/second prefill. For a short cleanup prompt (~200–400 output tokens), that's the difference between a noticeable wait and a sub-second response. The cleanup step is the primary UX friction point in the daily-use flow.

**3. Eliminated asset problem.** Phi-2 int4 alone is 2.18 GB. Android APK limit is 100 MB, so models had to be delivered via first-run download and stored in app-specific storage — adding setup friction and storage footprint for a personal-use app. ML Kit GenAI models are managed by the OS and already present on Pixel 10 devices.

**4. Simpler integration surface.** ML Kit GenAI APIs are a few lines of Kotlin. ONNX Runtime required custom inference pipelines for both encoder/decoder Whisper passes and autoregressive Phi-2 decoding, including tokenizer management, KV-cache, and output post-processing. That's significant complexity for a v1 personal app.

**5. Google's stated direction.** MediaPipe (the previous recommendation for mobile GenAI) is in maintenance mode. ML Kit GenAI APIs are actively developed and are what Google ships on Pixel. Aligning with the platform owner's recommended stack reduces long-term maintenance risk.

---

## What We Get

- **Faster cleanup step** — sub-second LLM response on Pixel 10 Pro XL; previously estimated 3–5 seconds with Phi-2 on NNAPI
- **Better thermal profile** — Tensor TPU inference runs cooler than sustained CPU/NNAPI inference; matters for "reach for it daily" success criteria
- **Zero model asset management** — no first-run download UX, no storage footprint, no file path management
- **Streaming STT** — ML Kit Speech Recognition streams partial results in real time; Whisper ONNX required full audio capture before inference
- **Simpler codebase** — removes two custom inference pipelines; STT and cleanup are each a handful of API calls
- **Fully offline after setup** — inference runs entirely on-device via AICore; no internet required during use. Matters for the "always with you" phone use case where connectivity isn't guaranteed. (Exception: internet needed for first-time AICore initialization and initial model download — one-time setup only.)
- **Full data privacy** — audio, transcripts, and prompts never leave the device during normal use. No cloud STT call, no LLM API call. Privacy profile matches the ONNX Runtime approach we replaced. Caveat: Google controls the AICore/Gemini Nano runtime; monitor AICore data handling policy if this becomes a hard requirement.
- **Phase 0 work preserved as reference** — Whisper and Phi-2 ONNX files archived in `python/`; usable as a fallback if ML Kit pivot fails validation in Phase 2.1

---

## What We Give Up

- **Model portability.** ML Kit GenAI Advanced mode is Pixel 10 only today. If this app ever expands to other Android devices, Advanced STT won't be available — Basic mode (traditional on-device ASR, no Gemini Nano) is the fallback. ONNX Runtime would have worked on any Android device with sufficient RAM.
- **Control over the model.** We can't swap, fine-tune, or version Gemini Nano. Google updates it via AICore. A model update could change cleanup output quality without warning.
- **Phase 0 investment.** Conversion work (Whisper + Phi-2 → ONNX) is not reused. It's not wasted — it validated the toolchain and models — but it won't ship.

## Future Considerations / Watch Out For

### API stability
- **ML Kit GenAI Speech Recognition is Alpha.** No SLA, no deprecation policy. Breaking changes are possible at any time. Monitor [ML Kit release notes](https://developers.google.com/ml-kit/release-notes) before each development session.
- **ML Kit GenAI Prompt API is Beta.** More stable than Alpha but still pre-GA. Treat as "stable enough to build on, but don't skip the release notes."

### AICore dependencies
- **Locked bootloader required.** AICore does not run on devices with an unlocked bootloader. If the Pixel 10 Pro XL has an unlocked bootloader for development purposes, Advanced mode will fail with a FEATURE_NOT_FOUND error. Validate this in Phase 2.1 before any further build work.
- **Cold-start / reset behavior.** After a factory reset or AICore reinstall, the service can take minutes to hours to reinitialize before GenAI features are available. This is a known developer friction point, not a user-facing bug — but test it in Phase 8 to confirm behavior.
- **AICore version drift.** Google updates AICore (and therefore Gemini Nano) silently via Play Services. Cleanup quality or prompt behavior could shift between app versions. Budget time for regression testing after OS/AICore updates.

### Gemini Nano model control
- **Prompt sensitivity may change across Nano versions.** A prompt that works well today may behave differently after a Gemini Nano update. Keep cleanup prompts simple and testable; avoid complex formatting instructions that are fragile under model changes.
- **No fine-tuning, no few-shot persistence.** In-context learning (training pairs from Room) is the only lever for improving cleanup quality. The model itself cannot be adapted. This is an intentional constraint — document it so it's not revisited as a v1 scope item.

### Tensor ML SDK Beta (deferred)
- The Tensor ML SDK Beta (direct TPU access for custom models) was evaluated and deferred. It would allow running custom or fine-tuned models directly on the Tensor TPU — relevant if Gemini Nano quality proves insufficient for specific intents (e.g., highly structured Obsidian note formatting). Revisit post-v1 if cleanup quality becomes a limiting factor.
- Sign-up required: [Tensor ML SDK Beta access](https://services.google.com/fb/forms/tensor_ml_sdk_experimental_access)

### Device scope
- This stack is intentionally Pixel 10 only for v1. Any future expansion to non-Pixel Android or to older Pixel devices requires a fallback strategy for both STT (Basic mode or Whisper ONNX) and LLM cleanup (Phi-2 ONNX or cloud API). Do not design v1 APIs assuming portability.
